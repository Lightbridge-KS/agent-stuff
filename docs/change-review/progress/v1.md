## Behavioural fixture

A throwaway git repository with one planted defect per lens — a logic error, an
author-specific absolute path, a missing spec requirement plus unrequested behaviour,
a breach of a rule the fixture's `AGENTS.md` documents — and two valid exceptions: a
toy that uses a local fixture, and a progress note that records results at a commit.

| # | Case | Expected |
|---|---|---|
| 1 | One reviewer, all lenses | Four lens sections; each planted defect found; no finding on the exceptions |
| 2 | Documentation-only candidate | Cheaper model tier; correctness `Skipped` |
| 3 | Packet without a base or lens paths | `partial`; names what is missing |
| 4 | Index and working tree differ from the candidate | Findings match the candidate objects |
| 5 | After any review | File hashes and `git status` unchanged |
| 6 | Corrected candidate | `No findings` in every section |

Results are recorded here per harness, with the date and the harness version.

The fixture is not in this repository. The object IDs below resolve only in the
copies on the machine that ran the cases, so only that machine can rerun a case
against the same objects. Anywhere else, rebuild an equivalent fixture from this
description and record the new IDs with the results; the cases do not depend on
specific IDs. The second fixture (v2) is a small Python package with a `src` layout
that `uv sync` installs, an `AGENTS.md` with three mandatory coding rules, and a
requirements document:

- R-01: `percentile(values, p)` interpolates linearly at zero-based rank
  `p / 100 * (n - 1)`. R-02: empty input raises `ValueError`. R-03: `p` outside 0–100
  raises `ValueError`. R-04: the CLI accepts `--percentile P`. R-05: a report script
  takes an input CSV and prints one line to standard output. File output is out of
  scope.
- The defective candidate breaks R-01 (rank uses `n`, and the upper index overruns),
  omits R-03, adds an unrequested `--save-json`, hardcodes an author-specific input
  path in the report script and writes a file, documents an environment variable no
  code reads, and adds an untyped, undocumented function that calls `print()`.
- The documentation-only candidate adds that environment-variable claim and a
  reference to private session notes. The corrected candidate fixes all of it.

## Confirmed contracts

- The `unslop` skill owns the definition of human-facing prose; the prose lens and
  the main agent's lens assignment both read it there.
- The prose lens detects and cites rule numbers; the main agent rewrites. A missing
  `unslop` skill skips the lens and does not make the review partial.
- A missing spec source skips the spec lens; the human is asked only on a standalone
  review.
- A return that lacks a lens section gets one re-dispatch of that lens before the
  review is reported partial.
- When only the documentation-only tier is unavailable, the default tier reviews and
  the report says so. Any other dispatch failure pauses.
- A re-review dispatches every assigned lens on the new candidate, with the previous
  candidate ID and the prior dispositions.
- Codex model tiers use separate native roles; role pins override spawn arguments.
- Fresh context excludes parent conversation, but retains standing instructions.
- The candidate is two git object IDs. The reviewer never reads the working tree or
  the index.
- The reviewer inspects only and returns to the main agent; it never edits, executes
  the candidate, delegates, or asks the human.
- The return has one section per assigned lens. A missing section, a missing path, or
  mismatched IDs make the review partial.
- A review covers exactly one base and one candidate. A changed tree needs a new
  review, with one exception: a complete pass whose findings are all low and whose
  fixes change wording only closes without another dispatch, and the report says so.
- After a partial review, the next review is a full one against the base, with no
  previous candidate ID.
- Scaling splits lenses between reviewers, never files.
