# dicom-standard v1 — progress

Design (the decision): [`../design.md`](../design.md). Approved plan: Claude plan
`vivid-finding-valley` (2026-10-17), from KS's ask to "index and cache the DICOM standard so an
agent can query and explore when needed — e.g. PS3.15 Annex E, up to date".

## Decisions (resolved 💡)

- Cache root `~/.lightbridge/data/dicom-standard/` (KS: a `data/` namespace for mirrored
  reference datasets, not a flat `dicom-standard/`), `DICOM_STD_HOME` override.
- Lazy per-part pull; no `--all` on first run (KS).
- FTS5 keyword search only in v1; embeddings deferred (KS).
- Keep every edition's raw XML; the index holds one edition per part (KS + plan).
- Skill home `plugins/radiology/` straight away rather than `experiment/` (KS).
- Read verbs never touch the network; `--pull` opts in (plan, unchallenged).
- One ~1,700-line PEP 723 script (deid.py precedent) rather than a package.
- FTS docs at row granularity so a tag or attribute-name search lands on the table row.

## Deferred

- `diff <edition> <edition> REF` — compare a table or section across editions (raw XML per
  edition is already kept; needs a second, temporary index or a direct XML diff).
- Figures: cache the SVGs under `editions/<ed>/figures/` and render a path.
- Semantic search over `docs` (local Ollama embeddings) — only if keyword + TOC proves
  insufficient in practice.
- MCP wrapper around the CLI for harnesses without a shell.
- `source:` URL rewrite to the pinned edition once `current` rolls past the cached edition.
- Thead-less tables with a bold first row treated as a header (PS3.15 has one, E.1-1a, whose first
  row is data; PS3.3/16 indexed without surprises).
- Colspan "Include Table X" rows in PS3.3 module tables repeat the value across every column by
  design (dense grid); a display-only de-duplication for `--format md` would need span origins kept.

## Confirmed contracts

- Exit codes: `0` ok · `1` stale / not cached / not found · `2` fix the request · `3` network
  or environment. Read verbs never fetch; `--pull` opts in.
- Every `show`/`table`/`tag` ends with `source: DICOM PS3.<n> <edition> — <url>`; the URL base
  is the one the part was fetched from (`current/` or a pinned edition).
- Table cells are plain text; column keys are lowercase alnum of the header, unique substring
  matching, ambiguity exits 2 listing the columns.
- Index holds one edition per part; a schema bump or sha mismatch reindexes from the cached
  XML without network.
- A downloaded part whose size disagrees with `Content-Length` is rejected (exit 3), never
  indexed.
