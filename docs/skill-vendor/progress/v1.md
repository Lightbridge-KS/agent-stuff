# skill-vendor engine v1 — progress

Design (the decision): [`../design.md`](../design.md) — approved 2026-07-25 (KS).
One invariant (served skill bytes are known-good for the installed binary), three
knowledge sources: co-shipped / first-party tag / third-party attestation. Manifest
`~/.lightbridge/skill-vendors.toml` hand-edited in v1; `attest` is the only machine
writer; co-shipped entries included so doctor covers the whole Vendored category.

Origin: AGENTS.qmd *Skill vendors* terminology (agent-instruction, 2026-07-25) named
the detached-vendored pin obligation; this engine is its mechanism. First driver:
the `crabbox` skill — CLAUDE.md already points agents at it, but no registry serves
it yet.

## Open questions

- Semver parse fallback: some CLIs print bare `0.40.0`, some `tool 0.40.0 (sha)`,
  some need `version` subcommand — is "first semver in output" + `version-cmd`
  override enough? Decide when a real counterexample appears.
- Should `list` warn (not fail) on registry symlinks it doesn't manage that point
  into install trees — i.e. hand-made vendored links predating the engine?

## Confirmed contracts

- Doctor exit codes: 0 clean / 1 skew / 2 broken — external seam for `lb doctor`
  and hooks; do not repurpose.
- Registry entries managed by the engine always resolve through
  `~/.lightbridge/skill-vendors/worktrees/<name>/` (detached) or the install tree
  (co-shipped) — never a repo's live `main` checkout.
