## Verification

- Repository validation, the complete `just test` dry suite, Python/JavaScript syntax,
  and standalone skill packaging passed.
- `ASK_QMD_LIVE=1 uv run tests/test_ask_form_qmd.py`: 16 tests passed, including real
  Quarto compilation, a copied skill without sibling imports, project-config isolation,
  portable context/image links, source diagnostics, and archive relocation after
  working-source deletion.
- Browser acceptance: all nine types, Other, notes/comments, recommendation divergence,
  Thai text, keyboard submission, validation focus, narrow layout, theme/tab/input
  preservation, hidden-tab diagrams, enlargement, and frozen read-only reopen passed.
- With cache disabled, browser requests remained on the local receiver. A deliberately
  broken first diagram displayed an error while a later diagram and submission worked.
- Independent review found identifier collisions, recommendation and satisfiability
  gaps, and source-location errors. Fixes are covered by regression tests and the
  browser round-trip. Submission races, rejected requests, save failure, cancellation,
  staged persistence, and archive hash failures have hermetic coverage.
- Browser/platform coverage: Codex Chromium browser on macOS with Quarto 1.9.38.
  Windows, Linux desktop browsers, and screen-reader interaction were not verified.

## Confirmed contracts

Submitted forms share the existing `asks/*.md` inventory. Each Quarto form owns an
independent `_bundles/<ask-id>/` snapshot. Runtime tokens never enter that snapshot.
`open` uses frozen HTML and exposes no submission route. Copied theme/viewer code
has recorded source hashes and no runtime dependency on either sibling skill.
