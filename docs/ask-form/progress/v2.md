# ask-form v2 — rich content

Parent: [`v1.md`](v1.md). Design: [`../design.md`](../design.md) § *Rich content (v2)*.
Claude plan `elegant-purring-seahorse` (2026-09-23).

Origin: forms carry agent explanation, but the v1 renderer is thin — a mermaid fence in markdown
showed as code, code had no highlighting or copy, diagrams froze their theme, options could not carry
rich detail, and the record dropped every context pane. The proposal was reviewed through ask-form
itself on 2026-09-23 (record `asks/2026-09-23_0035_rich-content-for-ask-form-proposal.md`).

## Decisions (resolved 💡)

- GFM dialect (alerts, `<details>`, mermaid/diff fences), not Quarto `:::` divs: marked parses it and
  the saved record renders on GitHub and Obsidian.
- **Copy** rich-document's viewer behaviour (enlarge dialog, serial render queue, per-diagram error)
  into `static/rich.js`; no shared module while rich-document is experimental. *Superseded
  2026-10-10 for the enlarge dialog:* both skills now vendor one viewer, the `diagram-zoom` core
  from Lightbridge-KS/quarto-diagram-zoom; the render queue and error panel stay copied.
- **Vendor** pinned `mermaid@11.6.0` and `highlight.js@11.11.1`; CSP drops cdnjs; fully offline.
- `spec_version` stays 1: every addition is optional; answer shapes unchanged.
- Own hljs token palette on the glass tokens (no vendored theme CSS).
- Quote target: the card containing the selection, else the next question, else Comments.
- Split layout is sticky per segment (context run + the questions it precedes), not a global rail.

### v2.2 — clear a choice (plan `crystalline-soaring-bird`, 2026-09-27)

Origin: once a user picked a review decision, a single_select option or a matrix cell, nothing
returned the question to unanswered — radios cannot be unchecked natively and the review pills only
switch. KS wanted to undo a click and leave an item open for a chat with the agent. Design:
[`../design.md`](../design.md) § *Spec and answers*, **Clearing a choice**.

- [x] Docs: this section; design paragraph
- [x] `static/app.js`: `clearableRadios(root, onClear)` for single_select and matrix rows (the radio
      chosen before a click is tracked per name on `change`; a click on it unchecks); the Other text
      field's auto-check dispatches `change` so the tracker never goes stale; review pills clear on a
      second press, keeping a typed comment; a "Click again to clear" tooltip on the chosen control.
      Found on the way: Chromium sends no `click` for Space on a checked radio (keydown/keyup only),
      so the helper clears on Space's keyup and cancels both edges.
- [x] SKILL.md `metadata.version` → 2026-09-27 (no contract change)
- [x] Pane pass (real clicks, Space, arrows, Other, submit → `meta.skipped`); `just test`
- [x] KS pass in Safari: all seven checks *Works* (click again, arrows + Space, Other, grid row,
      review pill, comment kept, tooltip) — 2026-09-27 (record
      `asks/2026-09-27_2144_ask-form-v2-2-clear-a.md`)
- [ ] Landed on `main` via PR

## Deferred

- Glossary popovers (`spec.glossary`) — approved in principle, moved to a later milestone (KS, 2026-09-23).

## Rejected

- Option ↔ diagram highlight (`options[].highlight`): depends on Mermaid's internal SVG ids, fragile
  across versions (KS, 2026-09-23).
- A "Discuss" state on review items, for an item the user wants to talk over before deciding: the
  per-question note already carries that; clearing the decision is enough (KS, 2026-09-27).

## Resolved open questions (#64, KS 2026-09-23)

- Mermaid stays pinned at 11.6.0; an upgrade is a separate change with its own browser pass.
- Mermaid stays vendored (~2.7 MB) for offline, deterministic rendering.
- Layout and theme belong to the reader, not the spec (v2.1): the agent's `layout` is only a hint.

## Confirmed contracts

- Answer shapes, exit codes, stdout document and token scope are unchanged from v1; `spec_version` stays 1.
- CSP `script-src 'self'`; vendored `mermaid@11.6.0` (MIT, sha256 `e9dd0d9a…`, license banner
  prepended) and `highlight.js@11.11.1` (BSD-3, sha256 `c4a399dd…`), both loaded lazily.
- Every bundled file stays under 1 MiB (remote skill-bundle limit; guarded in `test_ask_form.py`).
  Mermaid therefore ships as `static/vendor/mermaid.min.js.gz` (the sha256 above is of the
  decompressed file); a static request with no plain file falls back to `<path>.gz`, served with
  `Content-Encoding: gzip`. Regenerate on upgrade with `gzip -9nc mermaid.min.js > mermaid.min.js.gz`
  (`-n` drops name and mtime, so the archive stays byte-reproducible).
- Mermaid runs with `securityLevel: "strict"`; its SVG is inserted without a second sanitizer.
- The Enlarge viewer is vendored `diagram-zoom@0.1.0` (MIT, Lightbridge-KS/quarto-diagram-zoom):
  `static/vendor/diagram-zoom.js` (sha256 `de83bd06…`) and `.css` (sha256 `2cb48ea0…`), loaded
  eagerly before `rich.js`, styled through `--dz-*` tokens in `styles.css`. `onClose` keeps the
  theme-change guard (no re-render while the SVG is in the dialog). Update by copying both files
  from a tagged release, never by editing them here.
- The record's raw JSON tail uses a fence longer than any backtick run in the spec.
